01 / PROBLEM

A finished document hides the decisions that made it.

Producing a useful guide, assessment, or audio lesson requires more than summarizing the source. Someone chooses which details to preserve, which ideas belong together, what context each writer needs, and which parts require review. Those choices often disappear into a long conversation.

When the source changes or a new agent takes over, the team has to reconstruct that reasoning. Lamina treats the production method as an explicit, revisable object. The intended users are teams building repeated document workflows whose outputs must remain correct as the material changes.

Proposed integration. The current guide pipeline and generic method runner share storage but retain separate orchestration.

A method needs conditions for use, a source representation, context-selection rules, and a policy for repair. A job graph executes the chosen plan. It cannot by itself decide whether a figure needs a separate reader or whether two writers need to agree on a disputed claim.

The paper specifies these boundaries, compares alternative coordination policies, and defines what would count as evidence that a retained method transfers to a new task.

Models interpret sources and write the content. Lamina determines which inputs they receive, when their work can run, and which results can be reused.

Integration gap

The guide pipeline does not yet run as a custom method. Automatic method selection, completed-prose coordination, visual source extraction, and podcast delivery require further work.

SCHEDULING

A dependency can dominate the runtime.

T ≥ max(W / p, D)

W is total service work, p is worker count, and D is the longest dependency path. This ideal lower bound explains why adding workers stops helping. Provider limits, queues, and retries add time.

REPAIR

Reuse depends on the inputs.

key = H(runtime, adapter, node, context)

Context includes the selected task fields, dependency outputs, and selected observations. A node reruns when this request changes. Its descendants rerun if their own inputs change.
