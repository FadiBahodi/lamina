# Evaluating Lamina

Lamina's current tests establish data contracts and a reproducible export. They do not establish complete source comprehension, factual correctness, durable learning, or realistic case performance. This document separates what the code checks today from studies worth running before those claims are made. It is an evaluation design, not a results report.

## Measurement rules

- Freeze the input corpus, source roles, adapter identity, prompts, code revision, evaluation tasks, and scoring rubric before comparing runs. Keep development material separate from held-out material and check for duplicate or paraphrased questions across that boundary.
- Report a unit of analysis for every rate: pages, atomic claims, concepts, lessons, questions, learners, case transitions, or audio minutes. A count of processed pages is not a count of understood ideas.
- Record numerator, denominator, sample-selection method, uncertainty interval, and failure examples. Stratify by document type, length, table/image density, and topic; macro-average across sources as well as reporting pooled counts.
- Have two qualified reviewers label a sample independently, then adjudicate disagreements. Report raw agreement and a suitable chance-adjusted statistic for nominal labels; neither agreement nor adjudication turns reviewers into an infallible gold standard. [Cohen's original agreement paper](https://journals.sagepub.com/doi/abs/10.1177/001316446002000104) defines one such statistic.
- Define acceptance conditions **before** seeing outcomes. A structural invariant may require zero violations. For empirical quality, choose a risk-appropriate target with domain experts and compare uncertainty intervals to a declared baseline; this document invents no pass percentage.

## Layered evaluation matrix

| Layer and unit | Implemented check | Proposed evaluation and acceptance design |
| --- | --- | --- |
| **Parsing**: file/page | UTF-8 text and Markdown are decomposed into ordered units; PDF text uses page locators; image-only PDF pages fail rather than silently disappearing; malformed batches are parsed before writes. | Hand-audit a stratified page sample against rendered originals. Label missing words, broken reading order, table relationships, headings, and page boundaries. Compare extraction alternatives on the *same* pages. Accept a source class only when its critical meaning survives at a predeclared rate; route unsupported classes to OCR/layout processing or explicit exclusion. |
| **Scan coverage**: source region | File hashes and unit IDs show what was ingested. The code does not identify visual regions or prove that a page's salient content was extracted. | For a representative document set, enumerate text blocks, tables, figures, captions, formulas, and image-only pages in the rendered source. Record which have a usable unit or an explicit unsupported marker. Report missed critical regions by type and source. A source with unreadable required regions should not receive a “complete” badge. |
| **Atomic extraction**: proposition | Each proposed concept cites an exact quote in a known teaching unit; assessment units are excluded. Quote occurrence is a byte-level check, not entailment. | Annotators first write atomic source propositions independently of Lamina, with locators and importance labels. Match output propositions to the adjudicated set; score supported precision, recall of important propositions, and invented/inverted claims separately. Blind the adjudicator to the adapter name. Include negation, quantities, conditions, and exceptions in the error taxonomy. |
| **Semantic merge**: raw concept pair | Every raw concept belongs to one canonical concept and every member's evidence survives reconciliation. | Label pairs or clusters as same idea, related but distinct, or conflicting. Measure harmful false merges, missed merges, and evidence preservation. A merge fails if it erases a condition or opposition even when every quote remains attached. Compare with an unmerged baseline; semantic preservation needs human judgment. |
| **Curriculum**: lesson/objective | Every extracted canonical concept is assigned once or explicitly deferred; prerequisites point backward; each authored lesson refers to its assigned concepts. | Review whether the ordering supports prerequisite understanding, whether high-priority concepts were deferred, and whether lesson boundaries reduce or increase cognitive work. Give reviewers the source and a baseline source-order outline. Acceptance should require that no safety-critical or task-critical concept is silently deferred and that reviewers can explain the sequence. This evaluates the *extracted set*, not total corpus coverage. |
| **Grounding**: claim/evidence pair | Exact quotations, known unit IDs, teaching roles, assigned-concept evidence, and export validation are enforced. | Decompose lesson sentences, answers, scenario findings, and audio claims into checkable claims. Label each supported, contradicted, or not established by the cited passage; allow multi-passage support. Report errors per output surface and inspect citation usefulness, not just citation presence. The [FEVER study](https://aclanthology.org/N18-1074/) is an example of claim labels paired with evidence sentences, but Lamina requires a source-specific rubric. |
| **Practice and transfer**: learner/task | Recall, contrast, and apply prompts exist and answers start hidden. Browser self-ratings are local notes. | Run a time-matched comparison against reading the same source or a simple source-linked question baseline. Predefine unseen near-transfer and changed-context tasks, delayed follow-up, and blinded answer scoring. Report learning gain and completion time together. The original [test-enhanced learning experiments](https://www.psychologicalscience.org/journals/psychological-science/j.1467-9280.2006.01693.x/) and [transfer experiment](https://doi.org/10.1037/a0019902) motivate testing these outcomes; they do not establish Lamina's efficacy. |
| **Scenario causality**: transition/path | A local examiner can release authored findings and one second event; a checklist can be ticked. This is a presentation flow. No candidate-action parser, conditional patient-state engine, separate patient clock, or synchronized remote room is implemented. | On an authored case graph, replay every meaningful treatment/omission path. Assert reachable endpoints, exclusive conflicting branches, correct simulated-time labels, and no future or private result in the candidate projection. Then conduct two-person runs: record examiner adjudications, release errors, contradictory facts, scoring disagreements, and whether the intended decision was elicitable. Accept the format only after both graph invariants and observed runs pass their declared rubric. |
| **Audio delivery and teaching**: script/minute | Lamina emits speech/pause script segments; browser speech is optional. No generated audio or audio audit is claimed. | If audio production is added, test the authored script separately from the delivered file. Compare transcription to script for omissions, numbers, names, and timing; inspect clipping, silence, intelligibility, chapter navigation, and actual listener playback. Independently test whether listeners can explain and transfer the taught distinctions. A clean transcript does not prove pedagogical value, and a good script does not prove a usable recording. |
| **Time and cost**: stage/build/accepted lesson | Cache, bounded retries, local parallel workers, and durable stage results are implemented. No performance or cost frontier is established. | Log wall time and resource/currency cost per stage, including failed attempts, retries, review cycles, and human repair. Report median and tail latency, time to first usable lesson, cost per *accepted* lesson, and quality at equal budget. Compare sequential, parallel, cached, and uncached runs on the same corpus; count human review time rather than treating it as free. |

## Proposed case graph and release review

This is a **proposal**, not a description of the current scenario renderer. Let an authored case be `G = (V, E)`. A node `v ∈ V` is a named patient state. An edge `e = (v, a, g, Δtₚ, v′) ∈ E` contains an examiner-asserted candidate action `a`, guard `g`, simulated patient-time advance `Δtₚ`, and successor state `v′`. Each edge has candidate-safe releases, private examiner interpretation, a next prompt, objective/rubric IDs, and source support. The oral clock `tₒ` remains separate from simulated patient time `tₚ`.

The executable part would be deliberately narrow: the examiner decides whether an utterance merits action ID `a`; deterministic code selects an authored transition and computes a candidate observation `O(v, R, candidate)` from state `v` and released set `R`. It would not infer treatment quality from free text or calculate biological responses. An append-only run log could replay examiner decisions, releases, withdrawals, marks, and both clocks. Static path tests could then catch contradictory branches and disclosure leaks. A human run remains necessary to judge clinical plausibility and usable pacing.

For release, a future review record should bind the *exact bytes* of an authored lesson/case, source-unit manifest, and media manifest to the reviewer, rubric, verdict, and unresolved issues. Any changed branch, answer, source, or image should stale the pass. Lamina **currently** caches stage results by request and adapter identity and blocks a `revise` review; it does **not** implement this independent, exact-hash case-publication gate. A second call through the same adapter must not be described as independent review.

## First experiment to run

Before scaling output volume, choose a small public corpus with prose, a table, a diagram, and a scanned page. Establish a source-region inventory and a human atomic-proposition set. Compare Lamina with a simple source-order outline and question baseline under matched time and cost. Inspect every false merge and unsupported output claim. For the scenario lane, hand-author one case with a success and omission branch, replay both candidate projections, and run it with two people. Publish the protocol, denominator, uncertainty, defects, and revisions alongside any result. Do not promote a structural pass into a claim of learning or case realism.
